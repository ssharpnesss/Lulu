# Дообучение антиспам-модели

Исходная модель: `assets/ruspam_model`. Результат: `assets/ruspam_model_finetuned`.
Бот автоматически на новую модель не переключается.

## Данные и разделение

- `result.json`: поле `text`, класс обычного сообщения (0).
- `info_result.json`: поле `spam`, класс спама (1).
- Разметка принята из принадлежности файлу согласно инструкции пользователя, без ручной проверки.
- Модель получает только исходный текст. Имена, идентификаторы отправителей и `gpt_response` не используются.
- Пустые записи исключены. Для группировки применяется NFKC, нижний регистр, замена ссылок, ников и чисел, удаление пунктуации и нормализация пробелов. Для сообщений только из символов сохраняется текст символов.
- Каждая группа представлена одним исходным текстом. Группы с обеими метками удалены целиком.
- SHA-256 группы определяет разделение 80/10/10. Пересечения групп между частями запрещены проверками.
- Из частей с seed=42 выбраны 12 000 обучающих, 2 000 проверочных и 4 000 тестовых сообщений, поровну каждого класса. Остальные данные не участвовали в данном запуске.

Полный аудит, размеры и хеши исходных файлов: `data_audit.json`.
Фактические выборки: `data/train.jsonl`, `data/validation.jsonl`, `data/test.jsonl`.
Они содержат пользовательские сообщения и исключены из Git.

## Обучение и сравнение

Все параметры исходной DeBERTa дообучаются одну эпоху: AdamW, learning rate 2e-5,
weight decay 0.01, эффективный batch 16, 10% warmup, линейное уменьшение learning rate,
gradient clipping 1.0. Максимум 256 токенов, динамическое дополнение последовательностей,
gradient checkpointing, float32, NVIDIA GTX 1650.

У исходной модели нет смысловых имён классов в конфигурации. Ориентация выходов
определяется исключительно на validation по ROC AUC. В новом config.json сохраняются
имена `ham`/`spam`. В данном запуске spam соответствует выходу 1.

Лучшая контрольная точка выбирается по F1 спама на validation каждые 3 000 обучающих
сообщений. Порог фиксирован: 0.5 у обеих моделей. Обе версии проходят одинаковую
обработку текста и один и тот же test. Test не используется для обучения, выбора
контрольной точки или настройки порога. Сохранённая модель повторно загружается перед
итоговой оценкой.

Результаты: `comparison.json`; история validation: `history.json`; журнал: `run.log`.
Предсказания обеих моделей для каждого тестового сообщения: `data/test_predictions.jsonl`.
`original_model_hash.json` позволяет проверить, что исходные веса не изменились.

## Ограничения интерпретации

- Тест сбалансирован 50/50 и очищен от повторов. Его accuracy и precision не равны
  ожидаемым показателям живого чата с другой долей спама.
- Группировка блокирует перечисленные простые варианты шаблонов, но не гарантирует
  отсутствие всех смысловых перефразировок. Разделение не изолирует авторов или даты.
- Разметка по источнику может содержать ошибки; независимой ручной разметки нет.
- Неизвестно, были ли эти сообщения в обучающих данных исходной модели.
- Сообщения длиннее 256 токенов обрезаются у обеих моделей; количества приведены в отчёте.
- Интервалы accuracy — Wilson 95% по сообщениям, без поправки на остаточную зависимость шаблонов.

## Повторение (PowerShell, из корня проекта)

```powershell
python -m venv .venv-training
python -m pip --python .venv-training/Scripts/python.exe install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
python -m pip --python .venv-training/Scripts/python.exe install -r training/requirements.txt
.venv-training/Scripts/python.exe scripts/prepare_spam_data.py
.venv-training/Scripts/python.exe -u scripts/train_spam.py
```

Точные версии установленных пакетов: `environment.lock.txt`. Для обучения нужна CUDA.
Повторный запуск перезапишет результаты дообучения; исходная модель не изменяется.
Seed фиксирован, но побитовая воспроизводимость вычислений на GPU не гарантируется.
